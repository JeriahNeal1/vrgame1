# Quest 3 Demo Scene Setup

Scene path: `Assets/_Project/Scenes/Quest3DemoScene.unity`

Build settings index: `1`, after `Assets/OutdoorsScene.unity`.

## Purpose

`Quest3DemoScene` is a compact Meta Quest 3 validation scene for the unified item, inventory, equipment, manifestation, melee, harvesting, placement, electrical, modifier, enchantment, and icon-generation foundations.

The scene is generated by the editor menu:

`Tools/VRGame/Scenes/Build Quest 3 Demo Scene`

The generator is implemented in:

`Assets/_Project/Scripts/Editor/Manifestation/Quest3DemoSceneBuilder.cs`

Runtime scene seeding and binding is implemented in:

`Assets/_Project/Scripts/Runtime/Items/Quest3DemoRuntimeBootstrap.cs`

## Quest Guidance Used

Meta Horizon Unity documentation was consulted through the `metahorizon` MCP server:

- `enable-multiview.md`: Meta documents Multiview as rendering both eye buffers in one pass and reducing CPU render-thread draw-call work.
- `gpu-tiled.md`: Meta documents Quest devices as tile-based mobile GPUs, so the demo uses a small static environment, low object count, simple materials, and baked-style lighting.
- `po-book-performance.md`: Meta performance guidance emphasizes fewer draw calls, less complex shaders, and mobile-appropriate art assets.

Unity OpenXR package documentation was also checked locally:

- `Library/PackageCache/com.unity.xr.openxr@*/Documentation~/features/metaquest.md`
- That package documents:
  - Symmetric Projection (Vulkan) for a stereo symmetric view and performance benefit across IPD values.
  - Optimize Buffer Discards (Vulkan) to allow 4x MSAA textures to be memoryless on Vulkan.
  - Multiview Render Regions Optimization (Vulkan), with Unity 6.2+ options `None`, `All Passes`, and `Final Pass`.

The builder adds three explicit spawn transforms under the player rig:

- `Quest3Demo_LeftHandSpawn`
- `Quest3Demo_RightHandSpawn`
- `Quest3Demo_FallbackSpawn`

`DefaultHandItemSpawner` uses these as hand/fallback placement targets. Generated physical item prefabs include rigidbodies, colliders, `WorldItemIdentity`, `WorldItemView`, and an `HVRGrabbable` component when the Hurricane type is available.

Full physical controller grip/release validation still requires testing on a Quest 3 or compatible OpenXR runtime with the headset and controllers active.

## Assumptions And Limitations

- The demo is a functional prototype scene, not final art or final performance tuning.
- The three-panel UI is generated as simple world-space UI and should be replaced with final VR art and interaction styling later.
- The icon assets are generated placeholder PNG sprites for every sample item; the full physical-prefab render icon generator remains available for designer use.
- The HexaBody/Hurricane rig is instantiated and item prefabs are Hurricane-compatible, but headset/controller runtime validation was not possible from this editor-only environment.
- OpenXR settings were applied by serialized Unity editor settings. Re-check the Android OpenXR feature group in Project Settings before a device build because Unity package layouts can change between versions.
- Baked-lighting intent is represented by static environment geometry and a baked-mode key light. A full light bake was not run.
