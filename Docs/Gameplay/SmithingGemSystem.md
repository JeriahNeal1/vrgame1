# Smithing And Gem Enchantment System

## Purpose

The smithing system lets a player place an equipment item on an anvil and strike it with a held smithing hammer to reroll its modifier through the existing `ItemAffixService`. The gem system lets a player insert stackable gem resources into valid equipment to apply or upgrade data-driven enchantments.

This is an extension layer over the existing item/inventory architecture. Runtime save/network state still stores only IDs and serializable value records.

## Authored Data

- `ItemDefinition`: Anvil, Smithing Hammer, Ruby Gem, and Sapphire Gem are generated by `Quest3DemoSceneBuilder`.
- `GemEnchantmentProfileDefinition`: maps a stackable gem item ID to an enchantment pool and apply behavior.
- `ModifierSetDefinition`: the demo anvil uses `demo.modifier_set.smithing_basic` as its reforge pool.
- `EnchantmentSetDefinition`: Ruby maps to the Ember pool, Sapphire maps to the Frost pool.

Gems are stackable non-equipment resources. They do not carry modifier/enchantment pools on the item definition itself because only equipment may receive modifiers and enchantments.

## Runtime Flow

1. Manifest an equipment item instance through the inventory portal.
2. Release it over a `SmithingStation` anvil.
3. Manifest the Smithing Hammer and strike the anvil target above the configured velocity threshold.
4. Each valid strike accumulates quality up to a cap.
5. When the required strike count is reached, `SmithingStation.CompleteForge` builds a `ReforgeContext` and calls `SmithingService.ApplySmithingStrike`.
6. `SmithingService` validates the hammer definition and delegates the actual modifier reroll to `ItemAffixService.RerollModifier`.

For gems:

1. Place a valid equipment item on the station.
2. Manifest a gem stack item and release it over the anvil.
3. `SmithingStation.NotifyGemReleasedOnStation` resolves the matching `GemEnchantmentProfileDefinition`.
4. The station calls `SmithingService.ApplyGemProfileFromWorldGem`, which delegates to `ItemAffixService.ApplyGemEnchantment`.
5. On success, the world gem object is destroyed. Because portal manifestation already reserved/removed the stack item, the station does not remove a second stack quantity for world-gem insertion.

## Persistence And Authority Rules

- `ItemInstanceState` stores applied `ModifierInstanceRecord` and `EnchantmentInstanceRecord` values only.
- Runtime state does not store ScriptableObject, prefab, scene object, or Hurricane VR references.
- Smithing and gem insertion are transaction-shaped local operations now and should become server-authoritative commands later.
- Manifested stack gems are considered consumed when their world object is destroyed after a successful insert.
- Direct inventory gem application should use `SmithingService.ApplyGemProfileFromInventoryStack`, which preflights the gem application, removes the stack, then applies the enchantment.

## Extension Points

- Add new gems by creating a stackable resource `ItemDefinition` plus a `GemEnchantmentProfileDefinition`.
- Add new reforge stations by creating a placed prefab with `SmithingStation` and a modifier pool override.
- Skill, station, timing, and strike quality bonuses flow through `ReforgeContext` and `GemEnchantmentContext`.
- Future VR polish can wire controller release events directly to:
  - `NotifyItemReleasedOnStation`
  - `NotifyGemReleasedOnStation`
  - `NotifyHammerStrike`
  - `CompleteForge`

## Validation

- `Tools/VRGame/Scenes/Build Quest 3 Demo Scene` includes smoke checks for smithing and gem insertion.
- `Tools/VRGame/Items/Run Smithing Gem Self Check` simulates:
  - creating a sword and hammer instance,
  - rerolling a modifier with a smithing strike,
  - applying Ruby once,
  - upgrading Ruby once,
  - rejecting conflicting Sapphire after Ember is present.

## Current Limitations

- The anvil has functional trigger/collision relays, but final hand-pose and socket polish should happen in prefabs.
- Strike quality currently uses impact velocity plus simple accumulated quality. Skill progression is a numeric stub.
- Gem insertion consumes a whole manifested gem item. Partial world stacks are not split yet.
